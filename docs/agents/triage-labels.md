# Triage Labels

The skills speak in terms of five canonical triage roles. This file maps those roles to the actual label strings used in this repo's issue tracker.

| Label in mattpocock/skills | Label in our tracker | Meaning                                  |
| -------------------------- | -------------------- | ---------------------------------------- |
| `needs-triage`             | `needs-triage`       | Maintainer needs to evaluate this issue  |
| `needs-info`               | `needs-info`         | Waiting on reporter for more information |
| `ready-for-agent`          | `ready`              | Fully specified, ready for an AFK agent  |
| `ready-for-human`          | `ready-for-human`    | Requires human implementation            |
| `wontfix`                  | `wontfix`            | Will not be actioned                     |

When a skill mentions a role (e.g. "apply the AFK-ready triage label"), use the corresponding label string from this table.

Issues labelled `notes` are running notes, not requests: `/triage-issues` and the Triage workflow skip them.

## The `ready` bar

In this repo `ready` means an agent may build the issue unattended: applying it starts the Implement workflow (see "Automation" in `issue-tracker.md`). Triage, by hand or by the Triage workflow, applies `ready` only when all of these hold:

- The change is small: about one module plus its tests, with no new dependencies.
- Every acceptance criterion can be checked by a test or a screenshot.
- For a bug: the agent reproduced it, or the cause is confirmed in the code.
- It doesn't touch `.github/`, secrets, deploy config, the storage schema or migrations, or print CSS.
- It leaves no product or design decision open.

A clear issue that fails the bar gets `ready-for-human`. The same bar is written into the Triage workflow's prompt, `.github/prompts/triage.md`: change both together.

## Automated triage

The Triage workflow triages each issue the owner opens (see "Automation" in `issue-tracker.md`). It leaves exactly one category label and exactly one of `ready`, `needs-info`, `ready-for-human` or `wontfix`, with a comment saying why. For `wontfix` it only recommends: the issue stays open until the owner closes it. Every comment and issue body it writes starts with `> *This was generated by AI during triage.*`

## Categories

Every triaged issue carries exactly one category label. This repo uses three:

| Label           | Meaning                                  |
| --------------- | ---------------------------------------- |
| `bug`           | Something is broken                      |
| `enhancement`   | New feature or improvement               |
| `documentation` | Docs-only change (no app code changes)   |

Edit the right-hand column to match whatever vocabulary you actually use.
