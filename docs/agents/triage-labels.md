# Triage Labels

The skills speak in terms of five canonical triage roles. This file maps those roles to the actual label strings used in this repo's issue tracker.

| Label in mattpocock/skills | Label in our tracker | Meaning                                  |
| -------------------------- | -------------------- | ---------------------------------------- |
| `needs-triage`             | `needs-triage`       | Maintainer needs to evaluate this issue  |
| `needs-info`               | `needs-info`         | Waiting on reporter for more information |
| `ready-for-agent`          | `ready`              | Fully specified, ready for an AFK agent  |
| `ready-for-human`          | `ready-for-human`    | Requires human implementation            |
| `wontfix`                  | `wontfix`            | Will not be actioned                     |

When a skill mentions a role (e.g. "apply the AFK-ready triage label"), use the corresponding label string from this table.

Issues labelled `notes` are running notes, not requests: `/triage-issues` and the Triage workflow skip them. The Triage workflow also skips spec parents, labelled `spec`.

## The `ready` bar

In this repo `ready` means an agent may build the issue unattended: applying it starts the Implement workflow (see "Automation" in `issue-tracker.md`). Triage, by hand or by the Triage workflow, applies `ready` only when all of these hold:

- The change is small: about one module plus its tests, with no new dependencies.
- Every acceptance criterion can be checked by a test, a screenshot or, for a config- or docs-only change, by reading the diff.
- For a bug: the agent reproduced it, or the cause is confirmed in the code.
- It needs nothing on the [hand-back list](issue-tracker.md#hand-back-list).
- It leaves no product or design decision open.

A clear issue that fails the bar gets `ready-for-human`. The Triage and Implement workflows read the bar from this section, so this is the only copy.

## Automated triage

The Triage workflow triages each issue the owner opens (see "Automation" in `issue-tracker.md`). It leaves exactly one category label and exactly one of `ready`, `needs-info`, `ready-for-human` or `wontfix`, with a comment saying why. For `wontfix` it only recommends: it applies the label and leaves the issue open in HITL, and the owner closes it as not planned or relabels it. Every comment and issue body it writes starts with `> *This was generated by AI during triage.*`

## Categories

Every triaged issue carries exactly one category label. This repo uses three:

| Label           | Meaning                                  |
| --------------- | ---------------------------------------- |
| `bug`           | Something is broken                      |
| `enhancement`   | New feature or improvement               |
| `documentation` | Docs-only change (no app code changes)   |

Edit the right-hand column to match whatever vocabulary you actually use.
